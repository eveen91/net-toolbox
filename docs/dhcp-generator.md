# DHCP Generator

**Infrastructure → DHCP Generator** prepares Check Point Gaia DHCPv4 configuration for R81.10 and R82.10. Rendering, network validation and optional ISC syntax checking reuse the portable engine from `/mnt/dhcp/dhcp-tool`. Source hashes are in `server/dhcp_generator/vendor/PROVENANCE.md`; the original project is unchanged.

## Workflow

1. Create a firewall configuration or import generator JSON.
2. Edit global options, subnets, interface/VIP addresses, dynamic pools and reservations; save the draft.
3. Open **Validate & publish**, validate the saved draft and review the generated text.
4. Enter a change description and publish an immutable version.
5. In **Versions**, download `dhcpd.conf`, inspect snapshots, compare two versions or restore one into the draft. Restoration leaves published versions unchanged and creates a new draft revision.

Drafts may omit pools or contain no subnets. Publication requires one active pool per active subnet. The engine rejects overlaps, duplicate host IDs/MACs, reservations in dynamic pools, and ranges containing gateway/interface/network/broadcast addresses. Options inherit global values unless overridden on a subnet. Inactive entries remain validated and stored but are omitted from generated configuration.

Import/export uses the portable generator's JSON format, not the source application's database dump. A synthetic example is in `server/tests/fixtures/dhcp_generator/mvp.json`. CSV workflows, deployment records and Django persistence are not migrated. Configurations are independent of IPAM and do not synchronize automatically.

## Storage and access

New `dhcp_configurations`, `dhcp_versions` and `dhcp_audit` tables use each tenant's existing `toolbox.db`; normal tenant database backups include them. Versions retain the configuration, generated bytes, SHA-256, profile, generator version, validation report, author, timestamp and description. SQLite triggers prevent updating/deleting versions. Draft writes and publication require `expectedRevision`; stale writes return HTTP 409. Audit and changes share one transaction. Publishing the same draft revision twice returns 409; edit or restore a draft to create another version.

Every endpoint requires the `dhcp-generator` feature permission. Administrators have access through `*`. Fresh installations include it in the seeded user role. Existing roles are preserved: grant **DHCP Generator** in the role editor. Existing login, CSRF and tenant membership checks apply, including artifact downloads.

## Syntax checking

Optionally set `DHCPD_PARSER_PATH` to a trusted absolute path of an ISC `dhcpd` executable. Without it, data validation runs and syntax is marked `parser_unavailable` in the report and UI. With it, the bounded checker runs a syntax-only subprocess; syntax/parser failures block publication. This does not verify compatibility with a target Gaia appliance. The module generates downloadable artifacts and does not deploy to a firewall.

## API

Base: `/api/dhcp-generator/configurations`

| Method | Suffix | Action |
| --- | --- | --- |
| GET / POST | empty | Search/page configurations / create draft |
| GET / PUT | `/{id}` | Read / save draft |
| POST | `/{id}/preview` | Validate/render saved draft |
| GET / POST | `/{id}/versions` | Page versions / publish with description |
| GET | `/{id}/versions/{uuid}` | Immutable snapshot |
| GET | `/{id}/versions/{uuid}/artifact` | Stored artifact download |
| POST | `/{id}/restore` | Restore scoped version with revision check |
| GET | `/{id}/diff?before={uuid}&after={uuid}` | Text and configuration JSON diff |
| GET | `/{id}/audit` | Paginated audit |

Lists default to 20 entries (maximum 100). JSON is limited to 1 MiB, 512 subnets and 10,000 reservations. Reservation editing shows 25 entries per page.
